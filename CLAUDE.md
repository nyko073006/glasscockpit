# Glasscockpit

Obsidian-Plugin „Glasscockpit“, ein Nachbau, Open Source unter MIT (Veröffentlichung ab Abend 25): Claude-Code-Sitzungen als Terminal-Ansichten in Obsidian. TypeScript, esbuild, Vitest, kein React. Gebaut für macOS arm64 und x64; x64 ist in Obsidian ungetestet (außerhalb: Ladeprobe unter Rosetta).

## Festlegungen (04.10.2026, nicht neu verhandeln)

- Name Glasscockpit (bis Abend 21 „Claude Cockpit“), Plugin-ID `glasscockpit` (vorher `claude-cockpit`; Umbenennung Abend 22).
- View-Typen `glasscockpit-terminal` und `glasscockpit-dashboard`, CSS-Präfix `cockpit-`, eigene Daten in der Plugin-`data.json` (lesen selbst, schreiben per `saveData`).
- Das private Arbeits-Repo (Pfad in `CLAUDE.local.md`) bleibt lokal, ohne Remote, kein Push. Das öffentliche Repo `nyko073006/glasscockpit` (lokal `~/Developer/glasscockpit`, ab Abend 25) entsteht per `npm run export-public` aus diesem Repo und wird nie von Hand bearbeitet. Es ist zuerst privat; öffentlich stellen, Tag und Release nur auf ausdrückliches Wort des Eigentümers.
- Deploy-Ziel (ab Abend 20): kein Pfad im Code. `npm run deploy` liest das Ziel aus der Umgebungsvariable `COCKPIT_DEPLOY_TARGET` oder aus `deploy.local.json` in der Repo-Wurzel (`{ "target": "<absoluter Pfad>" }`, steht in `.gitignore`, Vorlage `deploy.local.example.json`); Env geht vor Datei, leere Env zählt als nicht gesetzt. Fehlt beides, bricht Deploy mit Hinweis und Exit-Code 1 ab, vor jedem Schreibzugriff. Deploy kopiert `main.js`, `manifest.json`, `styles.css` und `native/` dorthin, kein Symlink. Auflösung (`resolveDeployTarget`) und Zielprüfung (`checkDeployTarget`, inklusive Sperre gegen `agentic-os`) stehen rein in `src/core/deploy-target.ts`. Für deploy wird Node ab 22.18 gebraucht, weil `scripts/deploy.mjs` diese TS-Datei direkt importiert.
- Rechteabfragen überspringen (ab Abend 20, vorher „Rechte immer an“): Einstellung `skipPermissions` (Abschnitt „Terminal“, Name „Rechteabfragen überspringen“, Vorgabe aus). An startet Claude mit `--dangerously-skip-permissions`. Der Wert wird bei jedem Start gelesen und wirkt nur auf neue Sitzungen. Kein Dialog, kein Pro-Tab-Flag, keine Warnung. Die Konstante `SKIP_PERMISSIONS` gibt es nicht mehr, nur `DEFAULT_SKIP_PERMISSIONS` in `src/core/constants.ts`.
- node-pty nur aus dem offiziellen Microsoft-Paket `node-pty`, exakt Version 1.1.0 (`npm install --save-exact`).

## Befehle

- `npm run build`: `tsc --noEmit`, dann esbuild nach `build/main.js` und `build/styles.css`.
- `npm test`: Vitest einmal durchlaufen lassen.
- `npm run deploy`: build, dann `scripts/deploy.mjs`. Obsidian liest `main.js` nur beim Laden, danach neu laden. Deploy kopiert node-pty aus `node_modules/node-pty` nach `native/darwin-arm64/` und `native/darwin-x64/` im Ziel (Paketstruktur, alte Ordner werden vorher gelöscht, nie überschrieben), setzt `chmod 755` und `xattr -cr`. Die Kopie steht in `scripts/lib/native-copy.ts` und wird vom Release mitgenutzt.
- `npm run release`: build, `check:public`, dann `scripts/lib/release.ts` packt `dist/<id>-<version>.zip` (`<id>/` mit `main.js`, `manifest.json`, `styles.css`, `LICENSE`, `THIRD-PARTY-NOTICES.md`, `native/` beider Plattformen; `spawn-helper` und `pty.node` mit 0755). Der Loader wählt nach `process.arch` (`nativePaths` wirft für alles außer macOS arm64/x64). Kein Tag, kein GitHub-Release.
- `npm run native-checksums`: schreibt `src/core/native-checksums.ts` neu (Pfad -> SHA256 jeder Datei in `native/darwin-<arch>/`, erzeugt über `copyNodePty` aus `node_modules/node-pty`, `scripts/lib/native-checksums.ts`). Nach jeder Änderung an node-pty oder `copyNodePty` ausführen; der Wächter `test/native-checksums.test.ts` wird sonst rot (vergleicht frisch erzeugt gegen die Datei, byte-genau).
- Release-Assets (ab Abend 26, Tag = Manifest-Version ohne `v`): `npm run release` legt zusätzlich in `dist/` ab: `glasscockpit-native-darwin-arm64.zip` und `-x64.zip` (Inhalt von `native/<ziel>/` direkt an der ZIP-Wurzel, `pty.node` und `spawn-helper` 0755) sowie `main.js`, `manifest.json`, `styles.css` einzeln (Store, BRAT). Vor dem Packen wird das Paket gegen `native-checksums.ts` geprüft, sonst Abbruch ohne `dist/`. Das Komplett-ZIP bleibt.
- Binär-Download (ab Abend 26, `src/host/native-download.ts`, Netz in `native-download-fetch.ts`): Einstellungen, Abschnitt „Binärdateien“, Knopf „Binärdateien laden“. Lädt per `requestUrl` (Zeitlimit `NATIVE_DOWNLOAD_TIMEOUT_MS`) von der festen Adresse `https://github.com/nyko073006/glasscockpit/releases/download/<Manifest-Version>/glasscockpit-native-darwin-<arch>.zip` in einen `mkdtemp`-Ordner im Plugin-Ordner (gleiches Volume, damit der Tausch ein `rename` ist), listet das ZIP vorher mit `unzip -Z1` (Pfad nach außen = Abbruch) und entpackt mit `/usr/bin/ditto -x -k` (Systemwerkzeug, fragt nie nach, übernimmt Rechte), liest den Baum mit `lstat` ohne Symlinks zu folgen und prüft mit `verifyNative` (`src/core/native-verify.ts`): Dateimenge exakt wie in `NATIVE_CHECKSUMS`, keine Zusatzdateien, keine Symlinks, jede Summe. Erst bei ok: `chmod 755` und `xattr -cr` am geprüften Baum, dann Tausch (altes `native/<ziel>/` wandert in den Temp-Ordner, bei Fehler zurück). Jeder Fehler lässt `native/` unverändert, Temp wird immer entfernt. Basis-URL und Summen sind Sicherheits-Invarianten und bewusst keine Einstellung: Wer sie ändern könnte, könnte dem Plugin beliebigen nativen Code unterschieben. Der `NativeLoader` merkt sich keine Fehler, der nächste Sitzungsstart lädt das neue `native/`. `native-verify.ts` hat eine eigene Zielliste (`DOWNLOAD_TARGETS`, Test prüft Gleichheit mit `NATIVE_TARGETS`), weil die Release-Skripte sie ohne weitere Importe unter Node laden.
- `npm run export-public -- <ziel> [--message "Text"]`: kopiert die getrackten Dateien ohne `handoffs/`, `CLAUDE.local.md`, `.publicignore` und dessen Einträge in ein bestehendes git-Repo, räumt Altes im Ziel weg, prüft dort `check:public` und committet. Kein Push. `scripts/lib/export-public.ts`.
- node-pty lädt `src/host/native-loader.ts` nur aus `native/` im Plugin-Ordner, erst `pty.node` direkt, dann `lib/index.js`. Grund: Der Loader von node-pty verdeckt dlopen-Fehler mit „Cannot find module“.

## Ordner

- `src/core/`: reine Logik, kein Import von `obsidian`, `electron`, `node-pty`.
- `src/host/`: Zugriff auf Obsidian, Electron und Node.
- `src/main.ts`: nur Verkabelung, immer `this.app`, nie `window.app`.
- Sitzungen (ab Abend 4): Das Plugin hält `SessionManager` und `ViewTracker`, der Leaf-State der Terminal-View ist nur `sessionId`. Die letzte geschlossene View beendet die Sitzung nach `KILL_GRACE_MS`. Command „Diagnose“ misst die leere Pane (PTY-Portionen, Puffer- und DOM-Zeile).
- Claude-Start (ab Abend 5): `src/host/launcher.ts` liest beim Laden einmal `$SHELL -i -l -c` (PATH und LANG zwischen Markern, 5 s Timeout, Rückfall feste Liste aus `src/core/login-path.ts`) und startet `claude` ohne Shell mit Argumenten und Env aus `src/core/claude-launch.ts`. Die Cockpit-`sessionId` ist zugleich `--session-id` von Claude Code. Was eine View startet, bestimmt der Sitzungseintrag (`kind`): `shell` startet eine Shell, `claude` und `agent` starten claude (ab Abend 7, vorher Request-Map). Art und Tab-Titel stehen als `meta` im SessionManager.
- Sitzungen (ab Abend 7): `data.json` hält `{ schemaVersion: 1, sessions: SessionRecord[], settings }`. `SessionRecord` = `id, name, kind (claude|agent|shell), agentName?, cwd, createdAt`. `SessionStore` (`src/core/session-store.ts`) hält alles im Speicher und schreibt entprellt (`SAVE_DEBOUNCE_MS`), `onunload` ruft `flush()`. Gelesen wird über `adapter.read` und `parseDataText`, nicht `loadData`: Obsidian (1.13.7, `readJson`) loggt kaputtes JSON nur („failed to read JSON“) und liefert `undefined` wie bei fehlender Datei, gemessen in der Abnahme am 04.10.2026; Wächter `test/load-data-wiring.test.ts`. Kaputte oder fremde Datei: Vorgaben plus Notice mit Grund, gespeichert wird erst bei einer Änderung. Vorher legt das Plugin eine Sicherung `data.json.kaputt-<stempel>` (lokale Zeit, `backupSuffix`) neben der Datei an und nennt sie in der Notice; scheitert die Kopie, steht das in der Notice und es geht weiter. Der Launcher bekommt den Eintrag (`plan(record)`); fehlt der Ordner, Fehlertext „Ordner fehlt“. Fortsetzen: Gibt es `~/.claude/projects/*/<id>.jsonl` (`transcriptExists`), startet claude mit `--resume <id>`, sonst `--session-id <id>`; gilt für wiederhergestellte Tabs und „Neu starten“. Unbekannte ID in der View: neuer Eintrag `claude` im Vault samt Notice. „Neue Sitzung“ (`src/host/new-session-modal.ts`): Vault, Home und jeder Ordner unter `settings.projectsRoot`, bei jedem Öffnen neu gelesen. Begrenzung: ab `settings.maxSessions` laufenden Sitzungen startet keine weitere (Fehlertext in der Pane). Aufräumen: `onLayoutReady` entfernt Einträge ohne Tab (`store.prune`), IDs aus `leaf.getViewState().state`, nie aus `leaf.view` (Hintergrund-Tabs sind noch `DeferredView`). Ein geschlossener Tab entfernt seinen Eintrag nicht sofort.
- `node_modules/node-pty/.../spawn-helper` ist nicht ausführbar (`posix_spawnp failed`). Probeläufe außerhalb von Obsidian deshalb gegen die eingespielte Kopie unter `native/` fahren.
